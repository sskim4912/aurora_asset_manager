# Aurora Asset Manager

화면과 저장 API는 Cloudflare Worker `aurora-asset-manager`에서 실행합니다. 자산 데이터와 사진은 GCP 프로젝트 `api-for-anythingllm-1`의 비공개 버킷 `aurora_asset_manager`에 저장합니다. 서비스 계정 JSON은 Worker Secret `GCP_SERVICE_ACCOUNT_JSON`에만 등록하고 해당 버킷에 Storage Object User 권한을 부여합니다.

배포: 저장소 루트에서 `npx wrangler deploy --keep-vars`. `worker.js`는 서버 코드이며 정적 파일로 배포하지 않습니다. 로컬 개발은 `wrangler dev`를 사용하며 GCP에 접근하려면 별도 개발용 인증을 안전하게 구성해야 합니다. 정적 HTTP 서버만으로는 저장·로그인이 동작하지 않습니다.

서버 세션 로그인 후 `/api/status`로 저장소 연결을 확인할 수 있습니다. `/api/data`의 `X-Generation`을 다음 PUT에 보내며, 충돌은 409로 반환합니다. 매 저장 전 원본은 버킷의 `backups/` 아래에 보관합니다. 사진은 같은 이름의 다른 파일을 덮어쓰지 않습니다.

GitHub의 기존 `assets.json`, `photos/`, `key.json`은 이전 보관본입니다. 현재 운영 데이터로 간주하거나 버킷에 재적용하지 마세요. 서비스 계정 JSON과 토큰은 소스·커밋·로그에 포함하지 마세요.

지도는 Google Maps JavaScript API만 사용합니다. 브라우저용 API 키에는 운영 사이트 주소 제한이 필요하며, 키가 없거나 지도 로드에 실패하면 오류 안내를 표시합니다. 다른 지도 SDK로 자동 전환하지 않습니다.

자재관리는 기존 분류의 ‘자재’에서 사용합니다. QR만 사용하며, 입고·사용·반출 등록·사무실 확정·돌아온 자재·파손·분할·보관함 처리를 지원합니다. 수량 단위는 소수 3자리 이내이며 EA·SET·BOX·ROLL은 정수입니다. 반출중 수량과 파손 수량은 사용 가능 재고에서 제외합니다. 다른 구역으로 돌아온 자재는 기존 보관 재고가 있으면 새 로트로 분리합니다.

데이터 버전은 10입니다. 기존 비품·공기구 데이터는 유지하며 자재 정보와 `materialOps`(처리 명령 원장), `materialOrders`(PO 품목 연결)를 추가합니다. `material-core.js`의 동일 규칙을 화면과 Worker에서 실행하고, 서버는 기존 원장 보존 및 새 처리 재실행 결과를 검사합니다. 원장·반출 증빙을 삭제하거나 기존 단위·세트 구성을 변경하지 마세요. 이전 앱은 저장을 거부하므로 배포 후 새로고침해야 합니다. 기존 비품 정기 실사에는 자재를 포함하지 않습니다. 자재 실사 차이는 ‘수량 조정’에서 담당자·사유와 함께 기록합니다.

자재 분류를 선택하면 목록이 먼저 열립니다. 엑셀 메뉴에서 입고 양식을 내려받고 작성한 파일을 올려 검토 후 일괄 등록할 수 있습니다. 양식의 회색 샘플 행은 `행 구분`이 `샘플(등록 제외)`인 동안 업로드에서 제외하며, 실제 자재는 다음 빈 줄에 작성합니다. 한 줄은 새 자재 묶음과 QR 하나이며, 세트는 세트구성품 시트에서 묶음 식별번호로 연결합니다. 여러 PL을 한 번에 처리하며 오류가 있으면 일부도 저장하지 않습니다. 같은 파일·같은 내용의 재등록을 차단하고 기존 재고를 덮어쓰지 않습니다. 한 파일은 10MB·자재 500줄·입고 건 100건 이내입니다. 내보내기는 현재 필터 목록과 전체 처리 이력을 포함하며 입고 양식과 구분합니다. OCR·오프라인 저장·기존 비품 정기 실사와의 자동 연동은 포함하지 않습니다.

검증: `node tests/material-core.test.cjs`, `node tests/material-worker.test.cjs`, `node tests/material-import.test.cjs`. 테스트는 가상 데이터·가상 GCS 및 임시 생성 인증 키를 사용하고 실제 운영 데이터에 접속하지 않습니다. `material-core.js`는 화면 정적 자산과 Worker 번들에 모두 포함해야 하며, 테스트 폴더는 배포에서 제외합니다.
