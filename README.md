# Aurora Asset Manager

화면과 저장 API는 Cloudflare Worker `aurora-asset-manager`에서 실행합니다. 자산 데이터와 사진은 GCP 프로젝트 `api-for-anythingllm-1`의 비공개 버킷 `aurora_asset_manager`에 저장합니다. 서비스 계정 JSON은 Worker Secret `GCP_SERVICE_ACCOUNT_JSON`에만 등록하고 해당 버킷에 Storage Object User 권한을 부여합니다.

배포: 저장소 루트에서 `npx wrangler deploy --keep-vars`. `worker.js`는 서버 코드이며 정적 파일로 배포하지 않습니다. 로컬 개발은 `wrangler dev`를 사용하며 GCP에 접근하려면 별도 개발용 인증을 안전하게 구성해야 합니다. 정적 HTTP 서버만으로는 저장·로그인이 동작하지 않습니다.

서버 세션 로그인 후 `/api/status`로 저장소 연결을 확인할 수 있습니다. `/api/data`의 `X-Generation`을 다음 PUT에 보내며, 충돌은 409로 반환합니다. 매 저장 전 원본은 버킷의 `backups/` 아래에 보관합니다. 사진은 같은 이름의 다른 파일을 덮어쓰지 않습니다.

GitHub의 기존 `assets.json`, `photos/`, `key.json`은 이전 보관본입니다. 현재 운영 데이터로 간주하거나 버킷에 재적용하지 마세요. 서비스 계정 JSON과 토큰은 소스·커밋·로그에 포함하지 마세요.

지도는 Google Maps JavaScript API만 사용합니다. 브라우저용 API 키에는 운영 사이트 주소 제한이 필요하며, 키가 없거나 지도 로드에 실패하면 오류 안내를 표시합니다. 다른 지도 SDK로 자동 전환하지 않습니다.

자재관리는 기존 분류의 ‘자재’에서 사용합니다. QR만 사용하며, 입고·사용·반출 등록·사무실 확정·돌아온 자재·파손·분할·보관함 처리를 지원합니다. 수량 단위는 소수 3자리 이내이며 EA·SET·BOX·ROLL은 정수입니다. 반출중 수량과 파손 수량은 사용 가능 재고에서 제외합니다. 새 자재는 하나의 QR 아래 구성품별 실제 총수량과 구역별 재고를 관리합니다. 일부 이동·다른 구역 반납 시 관리번호와 QR은 유지하고 구역별 수량만 이동합니다. 다른 구역에도 같은 QR을 재인쇄할 수 있으며, 스캔 후 작업할 구역을 선택합니다. 기존에 발급된 분할 QR과 원장은 그대로 보존합니다.

데이터 버전은 12입니다. 기존 비품·공기구 데이터는 유지하며 자재 정보와 `materialOps`(처리 명령 원장), `materialOrders`(PO 품목 연결), `materialPlaces`(대표 위치 참조)를 사용합니다. `material-core.js`의 동일 규칙을 화면과 Worker에서 실행하고, 서버는 기존 원장 보존 및 새 처리 재실행 결과를 검사합니다. 원장·반출 증빙을 삭제하거나 기존 단위·세트 구성을 변경하지 마세요. 이전 앱은 저장을 거부하므로 배포 후 새로고침해야 합니다. 기존 비품 정기 실사에는 자재를 포함하지 않습니다. 자재 실사 차이는 ‘수량 조정’에서 담당자·사유와 함께 기록합니다.

자재 분류를 선택하면 목록이 먼저 열립니다. 직접 입고는 공통 업체·PO·PL·보관 구역·입고일·입고자를 한 번 입력하고 품명·규격·실제 수량·단위 줄을 추가합니다. 입고자와 등록 담당자는 별도 기록하며, 저장 전에 QR 개수와 수량을 검토합니다. 미개봉은 서류 기준·실물 미확인을 표시하고 개봉 확인·수량 조정을 이력으로 남깁니다. 내용물 수량도 모르면 임의 수량으로 등록하지 않습니다.

대표 위치·GPS는 입고 건마다 한 번 지정하고 기본으로 참조합니다. 일반 자재와 묶음 구성품은 대표 위치를 사용하며, 다른 위치를 선택한 항목은 별도 좌표를 유지합니다. 구성품별 사진도 연결합니다. 입고 화면에서 사진 없이 지금 내 위치·지도 지정이 가능하고, GPS 오차가 50m를 초과하면 지도 지정 또는 재시도를 안내합니다. 사진 촬영은 비어 있는 대표 GPS만 확인하며 기존 개별 좌표를 덮어쓰지 않습니다. 대표 GPS 보정은 참조 중인 항목에만 반영하고, 실제 자재 이동은 구역별 수량 이동 이력으로 처리합니다. 기존 데이터의 독립 좌표는 자동으로 대표 위치에 연결하지 않습니다.

자재 엑셀은 12개 열(입력 유형, 품명, 규격, 수량, 단위, 보관 구역, PO No., PL No., 업체명, 입고일, 입고자, 비고)의 한 시트입니다. 일반 행마다 QR 하나, 묶음 대표행과 바로 아래 구성품은 합쳐 QR 하나를 생성합니다. 대표행의 수량·단위는 비우고 구성품에는 세트당 수량이 아닌 실제 총수량을 입력합니다. 구성품의 공통 정보는 비웁니다. 실물 확인 상태는 검토 화면에서 전체 적용하거나 행별로 바꿉니다. 회색 샘플(등록 제외)은 업로드에서 제외합니다. 이전 두 시트 양식은 구성품 총수량으로 환산해 검토하며 기존 재고를 덮어쓰지 않습니다.

업로드는 빈 행·앞뒤/숨은 공백·전각 문자·천 단위 쉼표·여러 날짜 표기를 정리합니다. 모호한 수량, 수식, 구성품 연결 오류 등은 행 번호로 표시하고 일부 저장을 막습니다. 같은 파일·같은 내용의 재등록을 차단합니다. 파일 10MB·QR 500개·전체 5,000행·입고 건 100건 이내입니다. 내보내기에는 구성품별·구역별 재고와 처리 이력을 포함합니다. OCR·오프라인 저장·기존 비품 정기 실사와의 자동 연동은 포함하지 않습니다.

검증: `node tests/material-core.test.cjs`, `node tests/material-worker.test.cjs`, `node tests/material-import.test.cjs`, `node tests/material-zones.test.cjs`, `node tests/material-excel.test.cjs`, `node tests/material-shared.test.cjs`. 테스트는 가상 데이터·가상 GCS 및 임시 생성 인증 키를 사용하고 실제 운영 데이터에 접속하지 않습니다. `material-core.js`는 화면 정적 자산과 Worker 번들에 모두 포함해야 하며, 테스트 폴더는 배포에서 제외합니다.

엑셀 기능은 첫 화면의 `엑셀 등록·다운로드` 메뉴에 비품·공기구와 자재로 나누어 제공합니다. 각 그룹의 양식 받기·일괄 등록·내보내기를 같은 순서로 배치하며, 입고 등록 화면에는 중복 버튼을 두지 않습니다. 회색 예제는 행 위치가 아닌 등록 제외 표시로 판단하고 검토 화면에 제외 건수를 표시합니다. 예제를 삭제해도 첫 실제 자료는 읽습니다. 자재가 없더라도 PC 표 헤더는 유지하고, 미등록 안내와 검색·필터 결과 없음 안내를 구분합니다. 휴대폰에서는 카드 영역에 안내합니다.

수량 이동 시 사진·GPS를 함께 추가할 수 있습니다. 기존 QR을 유지하며 출발 구역 재고와 제품 사진은 보존하고 도착 구역에 이동 사진과 좌표를 기록합니다. GPS를 얻지 못하면 사진만 저장하며 기존 좌표를 덮어쓰지 않습니다.

자재 목록은 입고 누계·반출 완료(반환 차감, 사용 처리 포함)·반출 확인 대기·남은 수량을 구성품별로 표시합니다. 남은 수량은 기존 원장의 사용 가능 수량이며 파손과 실사 조정은 보조 표시합니다. PO 다음 PL 순서로 조회하고 자재 보관함은 휴지통으로 표시합니다. 헤더·필터의 설명은 마우스 올림 또는 ⓘ 선택으로 확인합니다.
